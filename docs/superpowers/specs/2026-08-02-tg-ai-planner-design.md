# AI-планер в Telegram — дизайн-документ

**Дата:** 2026-08-02
**Проект:** `tg_planner`
**Заказчик и пользователи:** Даня и Женя (общий чат в Telegram, 2 человека)

---

## 1. Что делаем

Telegram-бота, которого добавляют в общий чат. Ему пишут дела человеческим языком
(«завтра в 15 к врачу», «каждый вторник вынести мусор»), он их запоминает,
напоминает в срок, показывает расписание на день и неделю и каждое утро присылает сводку.

**Жёсткое ограничение:** нулевая стоимость эксплуатации. Не пробный период, а постоянные
бесплатные лимиты, без привязки банковской карты.

## 2. Решения, принятые на старте

| Вопрос | Решение |
|---|---|
| Как бот слышит задачи | Только по обращению: упоминание `@bot`, реплай на сообщение бота, команда `/…` |
| Privacy mode Telegram | Оставляем **включённым** (по умолчанию) — Telegram не пересылает боту обычные сообщения чата |
| Разделение дел | Да, с автоопределением ответственного (Даня / Женя / общее) |
| Хостинг | Cloudflare Workers + D1 + Cron Triggers |
| AI | Cloudflare Workers AI (встроенный, без внешних ключей и VPN) |
| Часовой пояс | Europe/Moscow |
| Утренний дайджест | 10:00 МСК |
| Разбор текста | Гибрид: свой парсер русских дат, AI — подстраховка |

## 3. Стоимость

| Компонент | Сервис | Бесплатный лимит | Наша нагрузка |
|---|---|---|---|
| Исполнение кода | Cloudflare Workers | 100 000 запросов/сут | ~1 500/сут (cron раз в минуту + сообщения) |
| База данных | Cloudflare D1 | 5 ГБ, 5 млн чтений/сут | единицы МБ |
| Расписание | Cron Triggers | входит в Workers free | 1 триггер |
| Нейросеть | Workers AI | 10 000 neurons/сут | десятки вызовов/сут |
| Мессенджер | Telegram Bot API | безлимитно | — |

Итог: **0 ₽/мес**, карта не требуется.

## 4. Архитектура

```
Telegram ──webhook──► Cloudflare Worker ──► D1 (SQLite в облаке)
                            ▲
                      Cron  * * * * *
              «кому пора напомнить прямо сейчас?»
```

Бот не работает непрерывно. Telegram сам стучится по HTTP при новом сообщении (webhook),
Worker просыпается на десятки миллисекунд, отвечает и засыпает. Cron будит его раз в минуту
для проверки напоминаний. Отсюда точность напоминаний ±1 минута и мизерный расход лимитов.

### 4.1 Модули

Каждый файл отвечает ровно за одну вещь и тестируется отдельно.

| Файл | Ответственность | Зависит от |
|---|---|---|
| `src/index.js` | Точка входа: `fetch` (webhook) и `scheduled` (cron). Проверка секретного токена и белого списка чатов | router, reminders |
| `src/router.js` | Определить намерение: команда / новое дело / нажатие кнопки. Вызвать обработчик | parse, db, format |
| `src/parse/ru-dates.js` | Свой парсер русских дат, времени и повторов. Чистая функция: `(текст, сейчас) → {дата, повтор, остаток текста}` | ничего |
| `src/parse/ai.js` | Подстраховка нейросетью, отдаёт строгий JSON по схеме. Провайдер переключается настройкой | ничего |
| `src/parse/index.js` | Оркестратор: сначала `ru-dates`, при неудаче — `ai`, при неудаче — переспросить кнопками | ru-dates, ai |
| `src/db.js` | Все SQL-запросы к D1. Наружу — понятные функции (`createTask`, `tasksForDay`, `markDone`) | — |
| `src/format.js` | Оформление сообщений: карточка дела, список дня, неделя, дайджест. Чистые функции | — |
| `src/reminders.js` | Кому пора напомнить, отправка, защита от повторной отправки | db, telegram, format |
| `src/repeat.js` | Расчёт следующего срока для повторяющихся дел | ничего |
| `src/telegram.js` | Тонкий клиент Bot API: `sendMessage`, `editMessageText`, `answerCallbackQuery` | — |
| `migrations/0001_init.sql` | Схема базы | — |

Правило границ: `router` не знает SQL, `db` не знает про Telegram, `format` не ходит в сеть.
Парсер и форматтер — чистые функции, поэтому покрываются тестами без всякой инфраструктуры.

### 4.2 Схема данных

**`tasks`**

| Поле | Тип | Смысл |
|---|---|---|
| `id` | INTEGER PK | — |
| `chat_id` | INTEGER | В каком чате живёт дело |
| `title` | TEXT | Само дело, очищенное от даты |
| `due_at` | TEXT (UTC ISO) | Срок; NULL — дело без срока |
| `remind_at` | TEXT (UTC ISO) | Когда напомнить заранее; NULL — не напоминать |
| `assignee` | TEXT | `danya` / `zhenya` / `both` |
| `created_by` | INTEGER | tg user id автора |
| `status` | TEXT | `open` / `done` / `cancelled` |
| `repeat_rule` | TEXT | `weekly:2`, `monthly:5`, `daily`, NULL |
| `parent_id` | INTEGER | Для экземпляров повторяющегося дела |
| `notified_pre` | INTEGER | 0/1 — предупреждение отправлено |
| `notified_due` | INTEGER | 0/1 — напоминание в момент отправлено |
| `created_at` | TEXT | — |

**`chats`**: `chat_id`, `tz` (`Europe/Moscow`), `digest_time` (`10:00`), `digest_enabled`, `remind_before_min` (30).
**`users`**: `tg_user_id`, `chat_id`, `alias` (`Даня` / `Женя`), `role` (`danya`/`zhenya`).

Время хранится строго в UTC, показывается в часовом поясе чата. Конвертация — через `Intl.DateTimeFormat`
с указанием таймзоны, чтобы переход на другое время и поездки ничего не ломали.

## 5. Сценарии

### 5.1 Добавление дела

Триггер: упоминание бота, реплай на его сообщение или `/добавить`.

1. Отрезаем упоминание, отдаём текст в `parse`.
2. `ru-dates` пытается сам: «завтра», «послезавтра», «в пятницу», «через 2 часа», «через 20 минут»,
   «5 марта», «31 декабря», «в 15:00», «в 15», «в полтретьего», «утром/днём/вечером»,
   «каждый вторник», «каждый день», «каждое 5-е число», «по будням».
3. Не вышло — идём в AI: на вход текст + текущие дата/время/таймзона, на выходе строгий JSON
   `{title, due_at, repeat_rule, assignee, confidence}`.
4. Ответственный: по умолчанию автор сообщения. Обращение в тексте («Жень, …», «нам надо») —
   переопределяет.
5. Ответ — карточка:

```
📌 К врачу
🗓 завтра, 5 августа, 15:00
👤 Даня · 🔔 напомню за 30 мин
[✅ Готово] [⏰ Перенести] [✏️ Изменить] [🗑]
```

6. Дата не распозналась вовсе — бот не гадает, а спрашивает кнопками:
   `[Сегодня] [Завтра] [Выбрать дату] [Без срока]`.

### 5.2 Напоминания

Cron раз в минуту:
- дела, у которых `remind_at <= сейчас` и `notified_pre = 0` → предупреждение за 30 минут;
- дела, у которых `due_at <= сейчас` и `notified_due = 0` → напоминание в момент;
- флаг ставится в той же транзакции, что и отправка, — двух одинаковых напоминаний не будет;
- в 10:00 по таймзоне чата — дайджест.

Кнопка «⏰ Перенести» разворачивается в `[+15 мин] [+1 час] [Вечером] [Завтра]`.

### 5.3 Расписание

`/день`, `/завтра`, `/неделя` — список, сгруппированный по дням, время слева, ответственный эмодзи.
Просроченное — отдельным блоком сверху. `/мои` — фильтр по себе. `/все` — открытые дела без срока.

### 5.4 Повторяющиеся дела

При отметке «готово» у дела с `repeat_rule` бот сразу создаёт следующий экземпляр
(`parent_id` указывает на исходное). Пропущенные повторы не накапливаются: если мусор
не вынесли три вторника подряд, висит одно дело, а не три.

## 6. Ошибки и отказы

| Что случилось | Поведение |
|---|---|
| AI недоступен или лимит исчерпан | Работает свой парсер; если и он не смог — бот спрашивает дату кнопками. Функциональность не теряется |
| D1 недоступна | Бот отвечает «не смог сохранить, повтори» — молча терять дела нельзя |
| Telegram вернул ошибку при отправке напоминания | Флаг `notified` не ставится, попытка повторится на следующей минуте |
| Cron не сработал (сбой платформы) | Догоняющая логика: выбираются все просроченные неотправленные, а не только текущая минута |
| Сообщение от чужого чата | Отбрасывается по белому списку, в лог |

## 7. Безопасность

- Секретный токен вебхука (`X-Telegram-Bot-Api-Secret-Token`): запрос без него отвергается.
- Белый список `chat_id` — бот обслуживает только разрешённые чаты.
- Токен бота и ключи — в секретах Cloudflare (`wrangler secret put`), не в коде и не в git.
- Privacy mode включён: личная переписка физически не поступает боту.

## 8. Тестирование

- **Юнит-тесты** (vitest) на `ru-dates`: таблица из десятков русских формулировок → ожидаемая дата,
  с зафиксированным «сейчас». Плюс граничные случаи: конец месяца, 29 февраля, полночь, «в пятницу»
  в пятницу вечером.
- **Юнит-тесты** на `format` и `repeat` — тоже чистые функции.
- **Интеграционные** на `reminders` с подставным временем и подставным клиентом Telegram:
  проверяем, что напоминание уходит один раз и не уходит дважды.
- **Живая проверка** в отдельной тестовой группе до подключения к рабочему чату.

Разработка ведётся по TDD: сначала тест на поведение, потом код.

## 9. Что делает Даня руками

1. `@BotFather` → создать бота → получить токен (5 минут).
2. Регистрация на Cloudflare — бесплатный аккаунт, без карты (5 минут).
3. Добавить бота в чат и один раз выполнить команду инициализации.

Всё остальное — деплой, миграции, настройка вебхука и cron — делается скриптами из проекта.

## 10. Сознательно НЕ делаем в v1 (YAGNI)

Голосовые сообщения → задача; синхронизация с Google Calendar; веб-интерфейс; теги и проекты;
подзадачи; вложения; несколько чатов с разными настройками; статистика продуктивности.

Всё это добавляется поверх, если реально понадобится.
