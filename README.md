# 🗓 Планер — Telegram-бот, который понимает человеческий язык

[![tests](https://github.com/escapist001/tg-planner/actions/workflows/test.yml/badge.svg)](https://github.com/escapist001/tg-planner/actions/workflows/test.yml)
[![license](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![cost](https://img.shields.io/badge/стоимость-0%20%E2%82%BD%2F%D0%BC%D0%B5%D1%81-brightgreen)](#стоимость)

Бот для общего чата: пишешь ему «завтра в 15 к врачу» или «каждый вторник вынести мусор» — он
запоминает, напоминает в срок и ведёт расписание на день и неделю. Работает на бесплатных
тарифах Cloudflare: **0 ₽ в месяц**, без привязки карты.

```
Ты:  @djplanner_bot завтра в 15:00 к врачу

Бот: 📌 К врачу
     🗓 завтра, 3 августа, 15:00
     👤 Даня
     [✅ Готово] [⏰ Перенести] [🗑]
     [👤 Даня] [👩 Женя] [👫 Оба]
```

## Что умеет

- **Понимает даты словами.** «через 2 часа», «в пятницу вечером», «5 марта», «15.08 в 16:00»,
  «в полтретьего», «послезавтра утром».
- **Повторяющиеся дела.** «каждый вторник», «каждое 5-е число», «по будням», «каждый день в 8».
  После отметки о выполнении сразу заводит следующий раз.
- **Напоминает дважды** — за 30 минут до срока и в сам момент. Кнопкой можно перенести на
  15 минут, час, вечер или завтра.
- **Знает, чьё дело.** По умолчанию — на автора. «Жень, купи корм» назначит на Женю,
  «нам надо к нотариусу» — на обоих.
- **Утренний дайджест.** Каждый день в 10:00 присылает, что запланировано и что просрочено.
- **Не читает вашу переписку.** Privacy mode Telegram оставлен включённым: бот получает только
  свои команды, упоминания и ответы на его сообщения. Остальное Telegram ему просто не отправляет.
- **HTTP API** — дела можно заводить снаружи, например из терминала или другого приложения.

## Что умеет сверх обычного планера

**Дела, которые вязнут.** Бот считает переносы. На пятом он перестаёт молча двигать дело и заводит
разговор: разбить на шаги, отдать партнёру, назначить жёсткий день или честно похоронить.
У дела с жёстким днём пропадают кнопки «+15 минут» и «+1 час» — именно ими оно доехало до пятого раза.

**Дробилка.** Нейросеть раскладывает дело-монстр на 3–5 конкретных шагов с датами. Одна кнопка
заводит всё, родительское дело закрывается.

**Штаб события.** Закреплённое сообщение с обратным отсчётом, полосой прогресса и ближайшими
дедлайнами. Обновляется само каждый час и при каждом закрытом деле.

```
💍 Свадьба — через 13 дней

█░░░░░░░░░░░  1 из 21

Ближайшее:
· 02.08 14:00 — Заехать в ТЦ и купить кольца 👫
· 03.08 12:00 — Позвонить в загс насчёт фамилии 👫

🔥 Сегодня горит: Заехать в ТЦ и купить кольца
```

**Прогон.** За три дня до события бот проходит по всем делам, включая закрытые, и спрашивает про
каждое: подрядчик точно подтвердил? За три дня ещё можно спасти что угодно, за три часа уже нет.

**Режим тихого дня.** В день события вся рутина молчит, вместо неё — таймлайн по часам с телефонами
подрядчиков. Вечером хвосты сами переезжают на послезавтра.

**Цепочки для контента.** Фраза «интеграция с брендом, пост 10 августа» разворачивается назад от
дедлайна: бриф → съёмка → монтаж → согласование → публикация → отчёт, с зазорами. Кросспост
раскидывает одну публикацию по четырём площадкам с подсказками по адаптации.

**Пачка дел одним сообщением.** Поток сознания нарезается нейросетью на отдельные дела с датами,
бот показывает черновик с кнопками — завести все или по одному.

**Передача дел.** Кнопка «Подхватишь?» присылает партнёру дело с контекстом: сколько у него дел
в этот день и где свободное окно. Отказ возвращает дело владельцу без тишины и недомолвок.

**Весы недели.** Две колонки, у кого сколько дел по дням. Перекос видно сразу, кнопка «Выровнять»
предлагает конкретные перебросы — и никогда не предлагает передать чужой маникюр или психолога.

**Ритуалы.** Ночной разбор дня с кнопкой «Раскидать хвосты» и воскресная сборка недели с опросом
про вечер для свидания — выбранный вечер бот потом защищает от новых дел.

**Вахта по питомцам.** Напоминание о прогулке приходит обоим с вопросом «Кто идёт?». Кто нажал,
тот и пошёл. Счётчик мягко показывает перекос до того, как он станет обидой.

**Полоса без просрочек.** Одна строка в дайджесте, без конфетти. В конце месяца — карточка-открытка
отдельным файлом.

## Как это устроено

```
Telegram ──webhook──► Cloudflare Worker ──► D1 (SQLite в облаке)
                            ▲
                      Cron  * * * * *
              «кому пора напомнить прямо сейчас?»
```

Бот не работает непрерывно. Telegram сам стучится по HTTP при новом сообщении, Worker
просыпается на десятки миллисекунд, отвечает и засыпает. Cron будит его раз в минуту проверить
напоминания. Отсюда точность ±1 минута при мизерном расходе лимитов.

### Разбор текста: сначала свой парсер, нейросеть — на подхвате

Наивное решение — гнать каждое сообщение в LLM. Здесь иначе: сперва работает собственный парсер
русских дат (`src/parse/ru-dates.js`), и он закрывает подавляющее большинство фраз мгновенно,
без сетевого запроса. Нейросеть (Workers AI) подключается, только когда формулировка вышла за
рамки правил — «надо бы к нотариусу где-то в середине недели».

Что это даёт: бот отвечает быстрее, не зависит от доступности LLM и практически не расходует
бесплатную квоту. Если нейросеть недоступна — функциональность не теряется, бот просто
переспросит срок кнопками.

> ⚠️ Грабли, на которые стоит посмотреть отдельно: в JavaScript `\b` (граница слова) определена
> через `\w`, а это только ASCII. С кириллицей она не срабатывает — `/\bзавтра\b/` не находит
> «завтра» вообще. Все русские регулярки в проекте используют явные юникодные границы
> `(?<![\p{L}\p{N}])…(?![\p{L}\p{N}])`. Тесты писались до кода и сразу на русском, поэтому баг
> всплыл на первом же прогоне.

### Модули

| Файл | Ответственность |
|---|---|
| `src/index.js` | Точка входа: webhook, cron, проверка секрета и белого списка чатов |
| `src/router.js` | Маршрутизация: команды, новые дела, нажатия кнопок |
| `src/parse/ru-dates.js` | Парсер русских дат, времени и повторов (чистая функция) |
| `src/parse/ai.js` | Разбор через Workers AI, строгий JSON, любая ошибка безопасна |
| `src/tasks.js` | Создание и закрытие дел — общая логика для бота и API |
| `src/db.js` | Все запросы к D1 |
| `src/format.js` | Тексты и клавиатуры сообщений |
| `src/reminders.js` | Напоминания и дайджест по расписанию |
| `src/time.js` | Часовые пояса: местное ↔ UTC |
| `src/repeat.js` | Следующий срок повторяющегося дела |
| `src/api.js` | HTTP API для внешних клиентов |
| `src/visual.js` | Псевдографика: прогресс-бары, карта недели, весы, месячная карточка |
| `src/features/wedding.js` | Штаб события, прогон, режим тихого дня |
| `src/features/zombie.js` | Пятый перенос и дробилка дел |
| `src/features/content.js` | Цепочки интеграций, кросспост, разбор пачки дел |
| `src/features/teamwork.js` | Передача дел и весы недели |
| `src/features/rituals.js` | Ночной разбор, воскресная сборка, полоса без просрочек |
| `src/features/pets.js` | Вахта по питомцам и ветеринарный календарь |
| `src/features/index.js` | Диспетчер: связывает фичи с роутером |

Границы модулей жёсткие: `router` не знает SQL, `db` не знает про Telegram, `format` не ходит в
сеть. Парсер, форматтер, время и повторы — чистые функции, поэтому покрыты тестами без всякой
инфраструктуры.

## Запуск у себя

Нужны Node.js 18+ и аккаунт Cloudflare (бесплатный, карта не требуется).

```bash
git clone https://github.com/escapist001/tg-planner.git
cd tg-planner
npm install
```

1. Создай бота у [@BotFather](https://t.me/BotFather) → получишь токен.
2. Создай базу и применить схему:
   ```bash
   npx wrangler d1 create tg-planner        # id из вывода → в wrangler.toml
   npx wrangler d1 migrations apply tg-planner --remote
   ```
3. Запиши секреты (они хранятся у Cloudflare, не в коде):
   ```bash
   npx wrangler secret put BOT_TOKEN        # токен от BotFather
   npx wrangler secret put BOT_USERNAME     # username бота без @
   npx wrangler secret put WEBHOOK_SECRET   # случайная строка
   npx wrangler secret put API_TOKEN        # случайная строка
   npx wrangler secret put ALLOWED_CHATS    # id разрешённых чатов через запятую
   ```
4. Задеплой и подключи Telegram:
   ```bash
   npm run deploy
   BOT_TOKEN=... WEBHOOK_SECRET=... WORKER_URL=https://... npm run webhook
   ```

Подробная инструкция с объяснением каждого шага — в [SETUP.md](SETUP.md).

## HTTP API

Авторизация — заголовок `Authorization: Bearer <API_TOKEN>`.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/tasks` | Создать дело: `{text, assignee?, chat_id?, notify?}` |
| `GET` | `/api/tasks?range=day\|tomorrow\|week\|undated` | Список дел |
| `POST` | `/api/tasks/:id/done` | Отметить выполненным |

Обёртка для терминала:

```bash
npm run add -- "в субботу в 12 забрать костюм"
npm run list -- week
npm run done -- 7
```

Текст разбирается тем же парсером, что и сообщения в чате, а созданное дело сразу появляется
в чате карточкой.

## Безопасность

- Вебхук защищён секретным заголовком `X-Telegram-Bot-Api-Secret-Token` — запрос без него отвергается.
- Белый список `chat_id`: бот обслуживает только разрешённые чаты, посторонние апдейты отбрасываются.
- Callback-кнопки проверяют, что дело принадлежит тому же чату, откуда пришло нажатие.
- HTTP API закрыт отдельным токеном, не совпадающим с секретом вебхука.
- Все SQL-запросы параметризованы; пользовательский текст экранируется перед вставкой в HTML-разметку.
- Секреты живут в хранилище Cloudflare и никогда не попадают в репозиторий.
- Повторные апдейты Telegram отсеиваются по `update_id` — дубликатов дел не будет.
